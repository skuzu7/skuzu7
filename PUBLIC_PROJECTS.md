## Maintenance conventions

- **Security research:** specify authorized scope, test environment, threat model, remediation, regression evidence and limitations.
- **Commercial/production candidates:** verify real authentication, access control, secrets, dependency provenance, licenses, tests and deployment configuration before release.
- **Learning exercises:** identify them as educational; do not label them production-ready; retain relevant historical context.
- **Reference/upstream code:** distinguish original contributions from copied, forked or derived work, and verify distribution terms.
- **Sensitive files:** avoid credentials, personal data, databases and private worksheets in Git. A tracked secret needs incident handling and possibly rotation; simply adding `.gitignore` is insufficient.

### Updating this directory

Check repository visibility and original authorship before edits. Do not add private repositories or private vulnerability findings to this public page. When a repository becomes private or is archived, update this inventory rather than assuming its old classification remains correct.
